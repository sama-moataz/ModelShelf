# ModelShelf audit: 26 November 2026

This audit was taken before the IDE restyle and the indexing fixes. The live checks ran against https://modelshelf.vercel.app with plain HTTP requests that did not follow redirects.

## Live HTTP checks before the change

| URL | Status | Notes |
| --- | --- | --- |
| `/estimator` | 308 → `/estimator/` | Vercel's trailing-slash redirect. It is permanent and creates no loop. |
| `/estimator/` | 200 | The intended canonical URL. |
| `/estimator/index.html` | **200** | Serves the same page under a second URL. The same applies to every route, because `/<route>/index.html` is served directly. |
| `/estimator/?entry=iris` | **200** | Resource pages link to estimator URLs with `?entry=<slug>`, so there are 25 crawlable parameter URLs. They are the likely source of the duplicate "Free-tier estimator" results. The canonical tag already points at `/estimator/`. |
| `/tools/estimator` | 308 → `/tools/estimator/` → 404 | This route never existed, so it serves no duplicate content. |
| `/llms.txt`, `/llms-full.txt` | 200 `text/plain; charset=utf-8` | No redirect and no authentication. |
| `/robots.txt` | 200 `text/plain` | Has explicit groups for search and AI crawlers, plus a `Sitemap:` line. |
| `/sitemap-index.xml` | 200 `application/xml` | |
| `/site.webmanifest` | **404** | There is no web app manifest. |
| `/favicon.ico` | 200 | A single 48×48 image of the old indigo mark. |
| `/does-not-exist/` | 404 | Real 404 status. |

## Branding

- The homepage already had WebSite, Organization and DataCatalog JSON-LD named "ModelShelf". The `vercel.app` host shows up as the "Vercel" site name in Google until Google reprocesses the site, and it can't be forced.
- The favicon set covered only `favicon.ico` (48×48) and an SVG. There was no 96×96 PNG, no 180×180 apple-touch-icon and no manifest.
- No Vercel logos or default Vercel metadata appear in the HTML. The only mention is `@vercel/analytics`, which is a cookie-free script with no visible branding.

## Resource titles

Every resource page used the pattern `<Name>: free dataset for AI/ML projects`. That repeats the same words across 30 pages, and it reads awkwardly when the name already ends in "Dataset", as in "Free Spoken Digit Dataset: free dataset for AI/ML projects".

## Content accuracy, from a desk review of the data file

- **AG News:** described as "120,000 news headlines". It is 127,600 articles (title plus description), 120,000 for training and 7,600 for testing, built by Zhang, Zhao and LeCun from A. Gulli's AG corpus.
- **California Housing:** the license said "Public (US Census derived)". The scikit-learn copy comes from StatLib (Pace & Barry, 1997), and its source states no explicit license.

These two were corrected first. The full primary-source re-check of all 30 entries followed the same day; its results are in [`resource-verification.md`](resource-verification.md).

## Found in this audit and fixed in the same change

- Added a 301 from every `/<route>/index.html` URL to `/<route>/`.
- Added a 301 from `/tools/estimator` to `/estimator/`.
- Estimator links now use `#entry=<slug>`. A fragment is never a separate URL to a crawler.
- Added a manifest and a full favicon set, and the homepage now has an explicit site name.
- Every resource page now has a written title of its own.
